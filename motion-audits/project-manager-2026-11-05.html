Motion.spring overshoots about 4% on tile arrangement

Shared/Motion.swift:33 · Canvas/CanvasBoardView.swift:929, 962 · Canvas/CanvasBoardView+Tiling.swift:269

  • (0.3, 1.35, 0.5, 1) peaks at 1.041 at 58% of the duration. On a 600 pt move, a tile passes its slot by about 24 pt and comes back.
  • The comment wants tiles to read as having "landed". The anti-checklist flags any bounce on a utility action, and tiling is one you do several times a day.
  • When the overshoot is wider than the gap between tiles, a tile can briefly overlap its neighbour.

Important · 4

No tempo or curve scale: 13 durations and three system curves

Durations in use: 0.12, 0.14, 0.15, 0.16, 0.18, 0.2, 0.22, 0.24, 0.25, 0.3, 0.32, 0.35, 0.4 s. Named system curves: Focus/FocusPanelChrome.swift:232 (.easeInEaseOut), CanvasSatelliteCompanion.swift:207, ProjectSplitViewController.swift:557 (.easeIn), and others

  • Things of the same kind run at different speeds. Panel resize is 0.22 s, panel snap 0.24 s, quick-bar resize 0.12 s, sidebar collapse 0.3 s.
  • .easeInEaseOut (0.42, 0, 0.58, 1) starts slowly. On a resize the user caused, the first ~60 ms feel like lag.
  • Motion already has carefully chosen custom curves (Phase). The remaining sites predate them.

enum Tempo {                       // Shared/Motion.swift
    static let quick = 0.12        // hover, chip, ghost, small fades
    static let standard = 0.2      // panel resize, snap, push-in, banners
    static let travel = 0.3        // board crossings, sidebar, multi-tile layout
}
enum Curve {
    static let out = CAMediaTimingFunction(controlPoints: 0.23, 1, 0.32, 1)   // things you caused
    static let inOut = CAMediaTimingFunction(controlPoints: 0.77, 0, 0.175, 1) // on-screen state changes
    static let exit = CAMediaTimingFunction(controlPoints: 0.4, 0, 1, 1)       // leaving; pair with ≤ 0.7× enter
}

Emil: custom curves always, and the same speed for the same kind of thing. Jakub: a scale is what lets anyone tune the whole app's feel later.

Through Emil's lens (primary)

Should this animate at all?

  • Findings 1, 3, 4: frequent motion is too long, bounces, or starts slowly.
  • Opportunity Focus-mode sidebar collapse (ProjectWindowController.swift:978, 0.3 s). Focus mode is toggled from the keyboard. Cut it to Tempo.standard, or snap it when the shortcut toggles it and animate only from a click.
  • The ⌥Tab switcher sets alphaValue = 1 with no fade (SwitcherController.swift:166). Keyboard-initiated, so instant is correct.
  • Tiled-workspace drags show a proxy and reflow once on drop, with no live reflow.
  • easeTopClearance steps a layout value on a timer, which the skill normally flags. The comment explains why: it keeps one clock with the sidebar's slide so the tiles can't flick between two layouts. Keep it, and it already respects Reduce Motion.
  • Quick-bar resize at 0.12 s is already in Emil's range.

Through Emil's lens: the system is restrained and its reasons are written down. The work left is making the most frequent motion (the focus push) faster and smaller, and taking the bounce out of tiling.

Through Jakub's lens (secondary)

Is this subtle and polished enough to ship?

  • Finding 1: the exit matches the entrance.
  • Opportunity HUD hints fade out more slowly than they fade in: CanvasPaneController.swift:2130–2133 (0.2 s in, 0.4 s out) and CanvasPageKeys.swift:338–351 (0.12 s in, 0.25 s out). Use 0.15 s in and 0.12 s out with Curve.exit. If the 0.4 s was meant to make the hint linger, hold it longer instead of fading it slowly.
  • Opportunity The panel resize at FocusPanelChrome.swift:230 invalidates the shadow only in the completion handler, so the stale outline its own comment describes probably shows for the whole 0.22 s (not checked live). Invalidate it at the start too, or crossfade the shadow.
  • The immersive stage leaves faster than it arrives (scrim 0.20 s in, 0.10 s out) and enters with scale 1.05 plus a 15 pt blur, which is the polished enter recipe.
  • An edit uses a feathered wipe; a navigation uses a directional push. Motion tells you what kind of change happened.
  • Motion.Phase, a lead/trail offset so zoom and placement trace a curve, is production-grade work.
  • CanvasTileControls uses a damped spring (response 0.24, damping 0.88) and checks Reduce Motion.

Through Jakub's lens: the craft is high where it has been designed (crossings, immersive stage, wipe vs push). The rough spots are older sites that never moved to the shared vocabulary.

Through Jhey's lens (selective)

What could the rare moments become?

  • Opportunity Finishing the last open task of a project happens about once per project. It's the one place a small moment fits: the project's dock mark ring closes, or the focus card settles with a brief tint of the project colour. Fade-only under Reduce Motion, and skipped when the project was completed from the CLI.
  • Opportunity The immersive stage is rare and chosen deliberately, so it can take 0.3 s instead of 0.2 s, more than the everyday UI gets.

Through Jhey's lens: Folio is right to keep delight out of the workflow. One or two rare, earned moments would give it character without slowing down anything you do a hundred times a day.

Suggested order

  • Add Motion.moving, Tempo, and Curve.
  • Fix the focus push (finding 1) in one shared file.
  • Move the ~25 bypassing sites onto Motion and add the script check.
  • Swap Motion.spring for settle on tiling, then judge it against the live board.
